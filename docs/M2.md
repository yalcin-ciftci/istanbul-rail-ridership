# M2 — five years (2021–2025): staging fixes + marts

Spec: Morks (2026-11-15). Implementation: Codex. Review/approval: Yalçın. Evidence: profile of all five years (`raw.rail_station_daily`, 1,903,203 rows).

## Findings (2021–2024 vs 2025)
- All years load with the same columns; every day present (2024: 366). Counts always integers, `passanger_cnt ≤ passage_cnt`.
- **Exact duplicates** (all source columns equal except `_id`): 2021 6,565 groups, 2024 1,706 groups; none in 2022/2023/2025.
- **Grain varies by year:** rows per day ≈ 1,880 (2021), 290 (2022/2023), 2,380 (2024), 370 (2025). Multi-row (date, station, line) groups are entrances/turnstile groups.
- **Mojibake in 2022/2023 names:** Windows-1254 text read as Windows-1252 (`Acýbadem`, `Yusufpaþa`, `ALÝBEYKÖY`, `Doðu`).
- **Station code present, name NULL:** 760 rows (2022: T3 and nostalgic tram; 2023: 31 rows on T5). Line-level rows (code and name NULL) exist in every year, mostly T3-KADIKOY-MODA and IETT NOSTALJIK TRAMVAY, plus a few single rows on other lines.
- Coordinates: 2021/2022/2024 mostly single-dot decimals (`28.9335555`); the M1 repair rule handles both formats. 2022 has 6,880 empty strings (→ NULL). `29.Eyl` in 2023 and 2025.
- Station codes are stable; 193 codes differ only by name spelling/mojibake or appear on two lines (transfer stations, e.g. AKE-AKS on M1 and T5 in 2021).

## Staging changes (`stg_rail_station_daily`)
1. **Name repair** for `station_name`, `district`, `line_name`: replace `ý→ı`, `Ý→İ`, `þ→ş`, `Þ→Ş`, `ð→ğ`, `Ð→Ğ` (macro `fix_turkish_mojibake(col)`; these letters do not occur in correct Turkish).
2. `is_line_level` stays `station_code is null`.
3. Test 4 `assert_station_fields_consistent` → FAIL only when `station_code is null and station_name is not null`. New warning `warn_station_name_missing`: `station_code is not null and station_name is null` (expected 760).
4. Unit test for `fix_turkish_mojibake` (all six letters + an already-correct name unchanged).
5. Empty-string station_code / station_name → NULL (they become line-level rows when the code is empty).

## New models
Layering: `staging` (views) → `intermediate` (view) → `marts` (tables). Schemas named exactly `intermediate` and `marts`.

1. **`int_rail_entrance_daily`** (view): staging rows with exact duplicates removed. Duplicate = same `resource_id`, `ride_date`, `line_name`, `station_code`, `station_name`, `district`, `longitude`, `latitude`, `journey_count`, `passenger_count` (NULLs equal). Keep the row with the smallest `source_row_id`. Warning test `warn_exact_duplicates_removed`: number of removed rows (expected 2021+2024 only).
2. **`dim_station`** (table, one row per `station_code`, line-level rows excluded):
   `station_code`, `station_name` (latest non-NULL by `ride_date`), `district` (latest non-NULL), `longitude`/`latitude` (average of the station's distinct non-NULL coordinate pairs in the latest year that has any; NULL if none), `first_seen_date`, `last_seen_date`, `line_count` (distinct lines ever).
3. **`dim_line`** (table, one row per `line_name`): `line_name`, `line_code` (text before the first `-` or space, e.g. `M4`, `T5`, `TCDD`, `IETT`), `has_line_level_rows` (bool), `first_seen_date`, `last_seen_date`.
4. **`fct_station_daily`** (table, grain `ride_date` × `station_code` × `line_name`, station rows only): `journey_count` (sum), `passenger_count` (sum), `entrance_rows` (count of entrance rows).
5. **`fct_line_daily`** (table, grain `ride_date` × `line_name`, **includes** line-level rows): `journey_count`, `passenger_count`, `station_count` (distinct station codes, 0 for line-level only), `has_line_level_rows`.

## Tests
- Grain uniqueness on every mart (combination of key columns; no packages → singular test or concatenated key with `unique`), `not_null` on keys, `relationships`: `fct_station_daily.station_code → dim_station`, `fct_*.line_name → dim_line`.
- **Reconciliation:** total `journey_count` per year in `fct_line_daily` = total in `int_rail_entrance_daily`; station-level part of `fct_line_daily` = total in `fct_station_daily`.
- `dim_station` coordinates within lon 27.9–29.95 / lat 40.7–41.6 when not NULL.
- Every station in `fct_station_daily` appears in `dim_station` with a non-NULL `station_name` (WARN if not).

## Known caveats (document in model descriptions)
- `passenger_count` summed over entrances may count one person more than once; finer-grained years (2021, 2024) inflate it more. **Use `journey_count` for comparisons across years.**
- Line-level rows have no station; they appear only in `fct_line_daily`.

## Done when
`dbt build` passes: ERROR 0; WARN only the listed warning tests; `pytest` and `ruff` green.

## 2022 journey-count anomaly (M2.1)

Model chain: staging → int_rail_entrance_deduped → int_journey_quality_daily → int_rail_entrance_daily → marts.

The 2022 investigation found a period in which almost all journey counts are
even and the journey/passenger ratio is approximately doubled. Monthly figures
from the investigation, reproduced against deduplicated entrances:

| Month | Even counts % | Journeys/passengers |
|---|---|---|
| 1 | 49.15 | 1.0268 |
| 2 | 49.72 | 1.0261 |
| 3 | 57.11 | 1.2103 |
| 4 | 100 | 2.1124 |
| 5 | 100 | 2.1619 |
| 6 | 100 | 2.1459 |
| 7 | 100 | 2.2245 |
| 8 | 100 | 2.2057 |
| 9 | 99.99 | 2.1765 |
| 10 | 99.86 | 2.1549 |
| 11 | 59.6 | 1.3247 |
| 12 | 50.29 | 1.0643 |

The daily rule flags `journey_suspect = true` when the share of deduplicated
entrance rows with even `journey_count` is **≥ 0.99** and
`sum(journey_count) / sum(passenger_count)` is **≥ 1.8**. The thresholds are
inclusive and both conditions must hold. The rule contains no year filter;
`assert_suspect_only_2022` fails if a flagged day falls outside 2022.

Historical M2.1 result (before the M5 update below): the build identified **218 days**, first **2022-03-28**, last **2022-11-02**.
Within that interval, **2022-10-31** and **2022-11-01** are not flagged; no dates
are missing from the daily quality model.

**M5 güncellemesi (2026-11-18):** Saatlik mutabakat (commit `f0159bb`)
sezgisel kuralın kaçırdığı 2022-10-31, 2022-11-01, 2022-11-03, 2022-11-04,
2022-11-05, 2022-11-06 ve 2022-11-07 günlerinde de iki kat sayımı doğruladı.
`journey_suspect_overrides` seed'i bu 7 günü ekler; güncel toplam **225 gün**,
pencere **2022-03-28…2022-11-07**. Eşikler ve satır bazında `// 2` tahmini
değişmedi. `journey_suspect_source`: kural tutarsa `rule` (seed'de de olsa),
yalnız ek listedeyse `hourly_override`, aksi halde NULL. Yukarıdaki işaretsiz
gün ifadesi tarihçedir; bu günler artık işaretlidir ve tahmin uyarısı geçerlidir.

### Source values not changed; estimate column added

`int_rail_entrance_deduped` retains the original deduplication logic and its
smallest-source-id unit test. `warn_exact_duplicates_removed` now compares
staging with that model and still reports **9706** removed rows.
`int_rail_entrance_daily` appends the daily boolean and a BIGINT estimate:
integer division of `journey_count` by 2 on flagged days, otherwise the original
`journey_count`. Both fact models append the sum of these estimates and
`has_suspect_journeys` (true if any input row is flagged). The estimate is not
an official IBB figure, and the flag does not prove the source anomaly's cause.

- Historical M2.1 caveat: 2022-10-31 and 2022-11-01 were unflagged. Superseded by the M5 update above: both are now hourly-confirmed suspect days; use the project estimate warning.

### Genel günlük hacim kalite kontrolü (2026-11-18)

`intermediate.int_daily_volume_anomaly` bir tablodur; hat-gün toplamlarının
tek kaynağı `marts.fct_line_daily` okunur. Her hat ve tüm hatların toplamı
(`scope=system`, `line_name='*'`) için önceki 8 takvim haftasının aynı hafta
günündeki **tahmin** medyanı hesaplanır; en az 4 gözlem gerekir. Tahmin/taban
oranı **>= 1,6** ise `spike`, **<= 0,35** ise `drop` olur.
Hat satırlarında öncelik: `no_baseline` → `new_line` → `low_volume` →
`spike`/`drop`/`none`. İlk görülme tarihi model girdisindeki hat başına
minimum `ride_date` değeridir. Bu tarihten itibaren ilk **180 gün**
(0–179 gün farkı) `new_line` olur; 180. günde normal değerlendirme başlar.
Taban medyanı **5.000'in altındaki** hatlar `low_volume` olur; tam 5.000
normal değerlendirilir. Sistem satırlarına bu iki hat kuralı uygulanmaz.
Kaynak/taban oranı ayrıca saklanır. Sayımlar değiştirilmez; model yayımlanan
marts'a eklenmez. Üç uyarı testi sıçrama, düşüş ve `fct_line_daily` min–max
aralığında sistem düzeyinde tamamen eksik tarihleri gösterir; grain ve
`accepted_values`, anahtar kolonların `not_null` ve sayım kolonlarının BIGINT
tip tutarlılığı testleri hata seviyesindedir.

2021-01-01–2025-12-31 gerçek koşusunda hat kuralları güncellendikten sonra
**259 spike** (19 sistem, 240 hat), **87 drop** (15 sistem, 72 hat),
**0 eksik tarih** bulundu; dbt `PASS=19 WARN=2 ERROR=0`.

sonucunu göstermez. Seçimde 10 unit test, 10 veri testi ve 1 model vardır.
