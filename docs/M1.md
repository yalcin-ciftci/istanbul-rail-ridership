# M1 — dbt staging: raw → stg_rail_station_daily

Spec: Morks (2026-11-15). Implementation: Codex. Review/approval: Yalçın.

## Goal
A dbt project in `transform/` that turns `raw.rail_station_daily` into a typed, cleaned staging view `staging.stg_rail_station_daily`, with tests that fail loudly when the source breaks the rules below.

## Findings from profiling the 2025 raw data (Morks, 2026-11-15)
- **Grain is entrance-day, not station-day.** 5,322 (date, station_number, line) combinations have 2–3 rows; none are exact duplicates. They differ in coordinates, counts and sometimes `town` (e.g. DUDULLU on M8 has two coordinates). These are separate entrances/turnstile groups of one station. **Staging keeps every source row.** Aggregation to station-day is M2's job.
- **Coordinates** are text with dots used like thousands separators: `289.335.555.555.556` = 28.9335555555556, `29.163.224` = 29.163224, `29.0` = 29.0. All non-null values start with `28`/`29` (longitude) and `40`/`41` (latitude). 23,858 rows (17.6%) have no coordinates → stay NULL.
- Dates: 2025-01-01 … 2025-12-31, all 365 days present.
- Counts: all cast to integers; min 1; `passanger_cnt` ≤ `passage_cnt` in every row.
- 23 lines, 358 station numbers, 345 station names, 34 towns (some rows have empty/NULL town). No leading/trailing spaces.
- **Found during M1 build (Codex, round 2):**
  - `Yenisahra` (YSR-YSR, M4) has longitude `29.Eyl` in all 365 rows: a spreadsheet turned the value into a date (29 September). The true value is lost.
  - Two lines report **line-level totals** with NULL `station_number` and `station_name`: `T3-KADIKOY-MODA` and `IETT NOSTALJIK TRAMVAY` (364 rows each). These are valid ridership rows without a station.

## Model: `staging.stg_rail_station_daily` (view)
Grain: one row per source row. Columns in this order:

| Column | Type | Rule |
|---|---|---|
| `row_key` | VARCHAR | `resource_id \|\| ':' \|\| cast(_id as varchar)` — unique across years |
| `source_row_id` | BIGINT | `_id` |
| `resource_id` | VARCHAR | as is |
| `ride_date` | DATE | `make_date(year, month, day)` from the three text columns |
| `line_name` | VARCHAR | `line` |
| `station_code` | VARCHAR | `station_number` (NULL for line-level rows) |
| `station_name` | VARCHAR | as is (NULL for line-level rows) |
| `is_line_level` | BOOLEAN | `station_code is null` — line total, not a station |
| `district` | VARCHAR | `town`; empty string → NULL |
| `longitude` | DOUBLE | coordinate repair (below) |
| `latitude` | DOUBLE | coordinate repair (below) |
| `journey_count` | BIGINT | `passage_cnt` (yolculuk) |
| `passenger_count` | BIGINT | `passanger_cnt` (yolcu; source typo fixed) |
| `source_last_modified` | TIMESTAMP | as is |
| `ingested_at` | TIMESTAMPTZ | as is |

**Coordinate repair** (macro `repair_coordinate(col)`): NULL, empty, or not matching `^[0-9.]*[0-9][0-9.]*$` (digits and dots, at least one digit) → NULL; otherwise remove every `.`, then put a decimal point after the first two digits and cast to DOUBLE: `cast(left(d, 2) || '.' || substr(d, 3) as double)` where `d = replace(col, '.', '')`. If `d` has exactly 2 digits, the result is that integer (e.g. `29` → 29.0).
**Pair rule:** if either repaired value of a row is NULL, both `longitude` and `latitude` are NULL (no half coordinates).

## Tests
- Generic: `row_key` unique + not_null; not_null on `source_row_id`, `resource_id`, `ride_date`, `line_name`, `is_line_level`, `journey_count`, `passenger_count`.
- Singular (`transform/tests/`):
  1. `assert_counts_valid`: rows where `journey_count < 0`, `passenger_count < 0` or `passenger_count > journey_count`.
  2. `assert_coordinates_in_istanbul`: non-NULL coordinates outside lon 27.9–29.95 / lat 40.7–41.6 (Marmaray reaches Darıca/Gebze in Kocaeli at ~40.79), or only one of the pair NULL.
  3. `assert_row_count_matches_raw`: staging row count ≠ raw row count.
  4. `assert_station_fields_consistent`: rows where exactly one of `station_code` / `station_name` is NULL.
- Singular **warnings** (`{{ config(severity='warn') }}`; visible, not blocking):
  5. `warn_invalid_source_coordinates`: raw rows whose non-empty `longitude` or `latitude` does not match `^[0-9.]*[0-9][0-9.]*$` (expected today: 365, Yenisahra).
  6. `warn_line_level_rows`: staging rows with `is_line_level` (expected today: 728, two lines).
- dbt **unit tests** for `repair_coordinate` through the model, covering: `289.335.555.555.556`, `29.163.224`, `291.636.965`, `29.0`, `410.533.333.333.333`, `4.101.234`, `29`, NULL, empty string, a non-numeric value (`29.Eyl`), a dots-only value (`.`) and the pair rule.

## Known caveats (for M2)
- Line-level rows (`is_line_level`) belong in line totals, not in station tables.
- Yenisahra has no coordinates in 2025; M2's station dimension may take them from another year.
- Summing `passenger_count` across a station's entrances may count a person twice if they enter through two entrances on the same day. `journey_count` sums safely.

## Done when
`uv run dbt build --project-dir transform --profiles-dir transform` passes (models + all tests) against the real `data/ulasim.duckdb`, and `uv run pytest -q` / `ruff` stay green.
