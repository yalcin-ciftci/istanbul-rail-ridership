# M3 — station groups, read-only MCP tool, agent

Spec: Morks (2026-11-15). Implementation: Codex (parts A and B in parallel). Review/approval: Yalçın.
Decisions (Yalçın, 2026-11-15): station grouping via a reviewed mapping table (seed); agent model Sonnet 5.5.

## Why station groups
Station codes are entrance/platform level. One physical station appears under several codes and name variants:
Yenikapı (`YNK-MR1..3`, `YNK-YN1/YN2`), Mahmutbey (`MHY-MH1..4`, `MHY-MT1..4`, case variants), Üsküdar (`USE-US1/US2`, `USE-MR1..3`),
direction suffixes (`Kartal (Batı)`, `Halkalı GÜNEY`), concourses (`Levent Batı konkors`), line prefixes (`M7 FULYA`, `M2 Levent`).
Neither the name nor the code prefix alone is reliable (`EMI-MR1` is Marmaray Sirkeci, `EMI-KBT` is Eminönü).
A **station group** is one physical station complex; transfer stations with the same name on different lines are one group
(Yenikapı M1+M2+Marmaray, Mahmutbey M3+M7). "Most crowded station" questions use groups.

## Part A — station group mapping (dbt side)

### A1. Draft generator `tools/draft_station_groups.py`
Reads `marts.dim_station` (read-only connection) and writes/updates `transform/seeds/station_group_map.csv`.
CSV columns (UTF-8, header, comma): `station_code,station_name,station_group,status,note`.
- `station_name`: current `dim_station.station_name` (for the reviewer; not used by models).
- `status`: `rule` (assigned by rules, no conflict), `flagged` (needs human review), `checked` (reviewed by a person).
- **Never overwrite existing rows.** If the CSV exists, only append codes missing from it (status per rules). Existing rows are kept byte-for-byte. Output sorted by `station_code`.

Normalisation key (apply in this order):
1. Turkish-aware lower case: `İ→i`, `I→ı`, then `lower()`; collapse runs of whitespace; trim.
2. Remove a trailing parenthesised part: `\s*\(.*\)$`.
3. Remove trailing `\s+konkors$`, `\s+hol\s+\d+$`.
4. Repeat until nothing changes, each pass in this order: remove a trailing line token `\s+[mtf]\d+$`; remove a trailing direction word `\s+(kuzey|güney|guney|doğu|dogu|batı|bati)$`; remove a trailing number that is separated by whitespace or a hyphen `(?:\s+|\s*-\s*)\d+$` (digits glued to a letter, as in `m3`, are not a separate number). (Revised 2026-11-15 after Codex found that the first version turned `mahmutbey m3` into `mahmutbey m`.)
5. Remove a leading line token `^[mtf]\d+\s+`.

Examples: `Yenikapı-2`→`yenikapı`; `MAHMUTBEY M3 HOL 3`→`mahmutbey`; `4 Levent 2 Güney`→`4 levent`; `Seyrantepe 1 Batı`→`seyrantepe`; `M7 YILDIZ 1`→`yıldız`; `Acıbadem (Doğu)`→`acıbadem`; `Levent Batı konkors`→`levent`.

`station_group` (display name) = key in Turkish title case per word (first letter upper case, with `i→İ`, `ı→I`): `yenikapı`→`Yenikapı`, `4 levent`→`4 Levent`, `ıhlamur`→`Ihlamur`.

Flag (`status=flagged`, reason in `note`, several reasons joined with `; `) when:
- (a) the group's codes have more than one code prefix (text before `-`), e.g. Aksaray `AKR-KBT` + `AKE-AKS`;
- (b) a code prefix is spread over more than one group, e.g. `ALK-ALM` in "Alibeyköy Metro" and `ALK-AL2` in "Alibeyköy";
- (c) `station_name` is NULL (`EMI-EMN`) — `station_group` left empty;
- (d) the key still contains a digit or one of the words `giriş`, `girişi`, `stad`, `metro`, `mah`, `mah.` after normalisation.

Otherwise `status=rule`. Rules (a) and (b) flag every row of the affected groups.

Tests (`tests/test_draft_station_groups.py`, `tmp_path` DuckDB, never the real DB): every example above; each flag rule; title case; append-only behaviour (an edited `checked` row survives a rerun unchanged; a new code is appended).

### A2. dbt
- `transform/dbt_project.yml`: seeds go to schema `marts` (`seeds: istanbul_ulasim: +schema: marts`), all seed column types `varchar`. Add `+persist_docs: {relation: true, columns: true}` for `marts` models and seeds, so descriptions become DuckDB comments (the MCP `sema` tool reads them). If dbt-duckdb does not persist the comments (check `duckdb_columns().comment` after the build), **stop and report**.
- `dim_station`: add column `station_group` (left join to the seed on `station_code`; empty string → NULL).
- New `marts.dim_station_group` (one row per non-NULL `station_group`): `station_group`, `station_codes` (comma-separated, sorted), `station_code_count`, `line_names` (comma-separated distinct lines from `fct_station_daily`, sorted), `districts` (comma-separated distinct non-NULL, sorted), `first_seen_date`, `last_seen_date`.
- New `marts.fct_station_group_daily` (grain `ride_date` × `station_group`): `journey_count`, `journey_count_estimated`, `passenger_count` (sums), `has_suspect_journeys` (bool_or), `line_count` (distinct lines). Built from `fct_station_daily` rows whose code has a group; rows without a group are excluded and counted by a warning test.
- Descriptions in `_marts.yml` (or a new yml next to it) for the seed, every new model and every new column, including the caveats: passenger_count may double count; use journey_count across years; 2022 estimate; groups are a reviewed mapping, not an IBB field.
- Tests:
  - seed: `station_code` unique and not_null; `status` accepted values `rule`, `flagged`, `checked`.
  - **error** if a `dim_station` code is missing from the seed (forces a seed update when new stations appear).
  - **warn** `warn_station_group_flagged`: number of `flagged` rows (expected > 0 now; 0 after review).
  - **warn** `warn_station_group_missing`: `dim_station` codes with NULL `station_group`.
  - grain uniqueness on both new models; reconciliation per year: `fct_station_group_daily.journey_count` total + journeys of codes without a group = `fct_station_daily` total.

### A3. Run
Generate the CSV once from the current DB, then `dbt build`. Morks then reviews `flagged` rows, edits the CSV (`status=checked`) and rebuilds; Yalçın looks over the result.

## Part B — read-only MCP server `ulasim_mcp/server.py`
Library: official MCP Python SDK **2.x** (`mcp>=2.3`, already in `pyproject.toml`): `from mcp.server.mcpserver import MCPServer`; tools via `@server.tool()`; stdio transport (`server.run()`). Version 1 names (`FastMCP`) do not exist.
Do not put code in the existing empty `mcp/` folder (a folder named `mcp` can shadow the package); leave that folder untouched.

Database path: env `ULASIM_DB`, default `<repo root>/data/ulasim.duckdb` (resolved from the file location, not the cwd).
**Every tool call opens its own connection and closes it** (DuckDB allows no reader while `dbt build` writes; a held connection would block dbt):
`duckdb.connect(path, read_only=True, config={"enable_external_access": False, "lock_configuration": True, "threads": 2})`.
If the file is locked or missing, return a clear Turkish error (`"Veritabanı şu an kullanılamıyor (güncelleniyor olabilir): ..."`), do not crash.

Tools (names and argument names exactly as written; tool descriptions in Turkish, short, saying when to use each):
1. `sema()` — tables and columns of schema `marts` only, with types and comments (`duckdb_tables()`, `duckdb_columns()`), plus `kapsam` (`min`/`max` of `fct_station_daily.ride_date`, null if the table is missing) and `uyarilar`: a fixed list of caveats — passenger_count may count one person more than once, use journey_count; between 2022-03-28 and 2022-11-02 journey counts look doubled in the source, use `journey_count_estimated` and say it is an estimate; line-level rows (no station) appear only in `fct_line_daily`; station groups are a reviewed mapping, not an IBB field; source: IBB Open Data (İBB Açık Veri Lisansı, CC BY 4.0 attribution).
2. `sorgu(sql: str, satir_siniri: int = 200)` — runs exactly **one** statement whose type is SELECT (check with `duckdb.extract_statements` → `StatementType.SELECT`; anything else, or 0 / 2+ statements, is rejected before execution). `satir_siniri` clamped to 1..1000. Fetch at most `satir_siniri + 1` rows to set `kesildi`. Timeout 30 s (env `ULASIM_SORGU_ZAMAN_ASIMI`, seconds): a `threading.Timer` calls `con.interrupt()`; return a Turkish timeout error. Result: `kolonlar`, `satirlar` (list of lists; date/datetime → ISO text, Decimal → float, other non-JSON values → str), `satir_sayisi`, `kesildi`, `sure_ms`. SQL errors return the DuckDB message, not a traceback.
3. `istasyon_bul(ad: str, en_fazla: int = 10)` — fuzzy search over `marts.dim_station` (`station_name`, `station_group`). Match key: Turkish-aware lower case, then fold `ı→i ğ→g ü→u ş→s ö→o ç→c`, collapse spaces. Score per candidate name: 1.0 equal key, 0.9 prefix, 0.8 substring, else `difflib.SequenceMatcher` ratio; drop < 0.6. Results grouped by `station_group` (best score per group), sorted by score desc then name: `station_group`, `skor`, `istasyon_kodlari`, `adlar`, `hatlar` (from `fct_station_daily`), `ilceler`, `ilk_tarih`, `son_tarih`. Blank `ad` → error. `en_fazla` clamped 1..50. If the `station_group` column does not exist yet (Part A not built), group by `station_name` instead.

Return values are JSON-serialisable dicts. Errors are returned as `{"hata": "..."}`, not raised, so the agent can read them.

Tests (`tests/test_ulasim_mcp.py`; a fixture builds a small DuckDB in `tmp_path` with `marts` tables and `COMMENT ON`; never the real DB):
- `sorgu`: valid SELECT and CTE; row cap and `kesildi`; clamping; rejects `INSERT`, `CREATE TABLE`, `DROP`, `COPY`, `ATTACH`, `SET`, `PRAGMA`, `INSTALL`/`LOAD`, two statements, empty text; `select * from read_csv('<a file in tmp_path>')` fails (external access off); timeout returns the timeout error within a few seconds (1 s timeout, a long `range()` aggregate); JSON types; missing DB file → Turkish error.
- `istasyon_bul`: `yenikapi` and `YENİKAPI` find Yenikapı; `uskudar` finds Üsküdar; typo `yenikpı`; blank → error; fallback without `station_group` column.
- `sema`: lists only `marts` tables with comments; `kapsam` dates; `uyarilar` non-empty.
- Integration: start the server with `mcp.client.stdio.stdio_client` (`uv run python ulasim_mcp/server.py`, `ULASIM_DB` → fixture DB), list tools (exactly the 3 names), call `sorgu` once.

Run command (add a row to the AGENTS.md command table): `uv run python ulasim_mcp/server.py`.
